# 仁王 3 存档改签助手

Windows 中文程序，使用原生弹窗同时展示准备事项和参考图片，其余步骤在控制台操作。保留关闭 Steam 云存档、手搓/魔改选择和两轮外部改签流程。主程序已由 Python 重写为 Rust，无第三方 Rust 依赖，也不需要 Python、Pillow 或 PyInstaller。外部 `双击我改签v0.5.exe` 沿用原工具。

## 使用

完整解压后运行 `双击我.exe`。构建后的完整发布目录位于 `dist/`，分发时请复制整个目录，不能仅复制 EXE。

1. 用目标账号在游戏中创建存档，确认主界面 CONTINUE 和 LOAD GAME 可点击，然后退出游戏。
2. 启动助手，在同一个弹窗中查看三项准备要求和标有“参考图片（游戏主界面示意）”的图片。点击“我已准备好，继续”进入账号选择；点击“取消”、关闭窗口或按 Escape 均退出操作。
3. 程序扫描 `%LOCALAPPDATA%\KoeiTecmo\NIOH3\Savedata` 中的数字账号目录。只有一个账号时自动选中；有多个时显示完整路径并要求明确选择。缺少系统存档的账号会在预检查中说明原因。
4. 选择手搓或魔改存档，核对账号和目标路径后确认。直接回车默认取消。
5. 助手请求 Steam 退出，为所选账号备份并修改云同步配置；不能自动处理时，必须手动关闭云同步并确认，才可继续。
6. 每轮在助手控制台中查看改签工具的实时输出，出现按任意键继续的提示时按键。看到工具明确提示“已为你改写签名”或改签成功后，输入 `y` 确认本轮结果。两轮都成功后才写回本地存档。

附带的 v0.5 改签工具使用 GBK 中文输出；助手会将标准输出和错误输出实时转换为 UTF-8，避免乱码，重定向到日志时也能保留正确中文。无需手动更改系统区域或终端代码页。

通常无需管理员权限。目录不存在、文件缺失、权限不足等错误会显示具体路径和系统原因。不同 Windows 用户拥有各自的存档位置；以另一个账户运行程序时应使用参数指定真实存档根目录。

## 路径与只读检查

程序不再包含固定存档账号。默认使用 `LOCALAPPDATA`；未设置时回退到 `USERPROFILE\AppData\Local`。资源优先从 EXE 旁及其有限层级的父目录寻找，也支持从 Cargo 的构建目录启动。

```powershell
# 只检查路径和资源：不退出 Steam、不创建备份、不运行改签工具、不修改存档
.\双击我.exe --check

# 自定义存档根目录（其下必须是各账号的数字子目录）
.\双击我.exe --savedata-root 'D:\游戏存档\Savedata'

# 从列出的账号中明确指定一个已有账号
.\双击我.exe --account <账号数字目录名>

# 自定义资源目录和 Steam 安装位置
.\双击我.exe --assets 'D:\仁王3助手' --steam-dir 'D:\Games\Steam'

.\双击我.exe --help

# 仅预览准备确认弹窗，关闭后退出，不读取或修改存档
.\双击我.exe --preview-confirmation
```

`--check` 检查指定账号或全部发现的账号，并分别检查两套源存档。它只验证路径、文件类型和必要文件非空，不保证写权限、Steam 云同步状态或改签结果。任何账号/存档组合检查失败时退出码为 1。

## 备份与失败处理

每次操作在资源目录下建立独立的 `backups/<账号>/<时间戳-进程号-序号>/`：

- `local/SYSTEMSAVEDATA00/SAVEDATA.BIN`：原系统存档。
- `local/SAVEDATA00/SAVEDATA.BIN`：原角色存档，仅在原文件存在时备份。
- `sharedconfig.vdf`：本次自动修改前的 Steam 配置（仅成功读取并备份时存在）。
- `staging/`：外部工具暂存文件的原始副本。
- `signed/`：两轮已经确认的改签结果。

签名失败、工具异常退出或用户未确认成功时，不写回本地游戏存档。程序独占同一改签工具目录，阻止多个助手实例同时改签；写回前还会检查本地存档是否在等待期间发生变化。暂存目录缺失时自动创建，原有暂存文件在结束时恢复。写回错误会尝试恢复原存档，并报告恢复结果和备份位置。

两个文件的替换无法组成一次跨文件原子操作。断电、进程被强制结束或磁盘故障时，应退出 Steam 和游戏，再将 `local/` 中的原文件复制回本次提示的账号目录。原本没有角色存档时，对应备份文件不会存在。Steam 云同步成功关闭后，即使取消改签也会保持关闭，可在 Steam 中手动调整。

助手不能解析第三方工具的内部成功状态，所以除了检查退出码和输出文件，还要求每轮人工确认。只有工具明确提示成功时才输入 `y`。

## 构建与测试

要求 Rust 1.85 或更新版本及相应的 Windows 链接器。MSVC 工具链需要 Visual Studio C++ Build Tools 和 Windows SDK；也可以使用 Windows GNU 工具链。本项目没有 Cargo 外部依赖。

```powershell
cargo fmt --check
cargo test --offline --locked
cargo build --release --offline --locked

# 运行测试并生成完整 dist/，同时更新根目录 双击我.exe
.\build.ps1 -Test
```

`build.ps1` 优先使用项目内已准备好的 `.build-tools/rustup/toolchains/1.85.0-x86_64-pc-windows-gnu`，否则使用当前配置的 Cargo。它不会安装或修改系统工具链。

测试仅使用临时目录、虚构文件和模拟改签回调，覆盖多账号发现、取消、两套存档、缺文件、Steam 账号匹配、VDF 修改、备份、写回失败恢复等情况。不要用完整交互流程作为自动化测试，不要对真实存档做试验。

## 源码

- `src/main.rs`：中文交互、参数、Steam 进程与外部工具调用。
- `src/confirmation.rs`：同时显示准备事项和参考图片的 Windows 原生确认弹窗。
- `src/signer.rs`：外部工具交互、GBK 输出的实时转码。
- `src/paths.rs`：存档账号和资源目录发现。
- `src/steam.rs`：所选账号的 Steam 配置匹配、VDF 编辑和备份。
- `src/workflow.rs`：预检查、备份、两轮改签与写回恢复。
- `HandMakeSave/`、`MagicMakeSave/`、`Nioh3SaveCertificateTool/`、`image.png`：沿用的资源。

资源目录中的中文名称必须保留。`target/`、`dist/`、`backups/`、本地构建工具和生成的 `双击我.exe` 不纳入版本控制。
